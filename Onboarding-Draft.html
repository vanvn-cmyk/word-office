Design notes & contracts

What the drawings above assume, and the rails they'd need to ride on. Copy is English-only per project rule.

Persona alignment

Anchor 35–44 proCopy tone is calm, confident, minimal marketing. No exclamation marks. Screen 2 speaks in workflow terms, not features. Screen 3 leads with the payoff ("we do the rest") before the ask.
Maturity 55+Body text ≥14.5pt. Trust badge is green, plain-language ("Encrypted at rest · Revoke anytime"). Paywall shows the cancel path before the purchase button. No dark patterns — the "Continue with free" is a full-width button, not a hidden link.
Both personasNever gate onboarding behind a paid feature. Face ID and folder access can both be skipped. Paywall is dismissible with a real "X" in the corner.

Flow & state

  • Trigger: @AppStorage("hasCompletedOnboarding") false → present OnboardingContainerView in .fullScreenCover from RootView.
  • Steps as enum OnboardingStep: Int, CaseIterable: .welcome → .value → .folderPermission → .faceID → .paywall.
  • Skip semantics: Screen 3 secondary ("I'll do this later") advances to step 4 without asking for folder access; Library will show empty-state with the same CTA on first launch. Screen 4 "Skip" advances to Paywall. Paywall "Continue with free" dismisses onboarding.
  • Non-linear back: Users can swipe back one step at any point; state is preserved (chosen folder bookmark, Face ID toggle) — never re-prompted in the same session.
  • Resume-safe: If app killed mid-onboarding, resume from last completed step; do not re-run system permission prompts if already granted.

Aha moment — Screen 3 (folder permission)

  • This is the pivotal screen. Everything else supports it.
  • Tap "Choose Folder" → present UIDocumentPickerViewController(forOpeningContentTypes:asCopy:false) with allowsMultipleSelection: false, type .folder.
  • Save security-scoped URL bookmark to Keychain (service: com.wordoffice.folderBookmarks) — per project-word-office-mvp-v2.
  • On success, immediately push Screen 4. Kick off FolderAutoScanService.scan(...) in the background so by the time onboarding closes, the Library already has documents. This is the payoff.
  • On failure or cancel from the system sheet, stay on Screen 3 with an inline error ("Couldn't access that folder. Try another?"). Never block progress permanently.

Paywall (Screen 5) integration

  • Reuse existing PaywallView + PaywallViewModel shipped in S18. The onboarding paywall passes a distinct PaywallEntryPoint.onboarding so analytics can separate onboarding conversions from mid-app upsells.
  • Screen 5 uses the same layout as the mid-app paywall — one visual identity, one paywall to maintain. Only the entry point tag differs.
  • Soft-paywall rules: "X" always visible top-right; secondary CTA is a full-width button, never a small text link; no forced trial. Fine print is legible (10.5pt+, not 8pt gray-on-gray).
  • Auto-renew disclosure and links to Terms & Privacy per App Store guideline 3.1.2(a).

MVVM + SOLID sketch

ViewOnboardingContainerView owns step routing. Each step is its own leaf view: WelcomeStepView, ValuePropsStepView, FolderPermissionStepView, FaceIDStepView. Paywall reuses existing PaywallView.
ViewModel@Observable final class OnboardingViewModel — holds currentStep, didGrantFolder, didEnableFaceID. Exposes advance(), skip(), complete(). No UIKit imports.
Services (DI)FolderPermissionService protocol + prod impl (wraps UIDocumentPicker + Keychain bookmark write). BiometricService protocol + prod impl (LAContext). OnboardingCompletionStore protocol backed by UserDefaults/App Group.
TestsSwift Testing suite: VM step transitions (all forward + skip paths), completion flag write, service protocol double for permission grant/deny. Target: 12–15 tests. No integration with real LAContext in tests.

Accessibility

  • All CTAs support Dynamic Type up to .accessibility3. Progress dots have accessibilityLabel "Step 3 of 4".
  • Illustrations get accessibilityHidden(true); headline+subhead carry meaning for VoiceOver.
  • Color contrast: brand button (#FF6B4A on white) verified ≥ 4.5:1 for text weight 600.

iPad adaptation

  • Same 5 steps. On regular width, center a 480pt-wide column; the illustration grows to ~360pt tall.
  • Do not use NavigationSplitView here — onboarding is a modal full-cover flow even on iPad.
  • Hardware keyboard: return = primary CTA, esc = secondary/skip.

Open questions — need user decision

Q1
Face ID step — keep or drop? Argument to drop: adds friction, most users won't need. Argument to keep: aligned with 55+ persona trust concerns, low-cost tap. Draft assumes keep, with clear Skip.
Q2
Paywall pricing shown ($9.99 / $39.99)? Placeholder. Real numbers pending competitive positioning research. If we want to be visibly cheaper than Adobe/OfficeSuite, target $2.99/mo or $19.99/yr.
Q3
Trial length — 7 days or 3 days? Draft uses 7. Some apps use 3 to force decision. Anchor persona is deliberate; 7 fits.
Q4
Screen 2 features — 3 or 4? Draft shows 3 (Edit, Scan, Sign). Adding "Merge & split PDF" makes it 4. Trade-off: more scannable vs. more feature completeness.
Q5
Name/personalization step? Some apps ask for user name early. Draft skips this — data isn't used anywhere in MVP, and it's friction. Recommendation: don't add.
Q6
Notifications permission? MVP does not use push (reminders are in-app filter per project-word-office-mvp-v2), so no permission prompt in onboarding. Confirm this is still true.
Q7
Brand color — is #FF6B4A the final choice? Draft uses warm orange. If the app's Color.dsBrandPrimary is a different hue, all buttons/accents should swap.

MVP variant · what changed & why

The lean flow reflects the 12-item MVP scope. Anything not in scope was cut here so the flow doesn't promise features that aren't shipping.

Delta from the full 5-screen version

Split · Each feature = its own screenPer your ask, features are 3 separate screens with Never lose track at the end: S1 Edit Office natively (Word · Excel · PowerPoint), S2 Tools built-in (Convert · Sign · Compress), S3 Never lose track (Tủ hồ sơ status tags — closes the feature sequence). ⚠ Compress currently sits in Phase 1 per project-word-office-mvp-v2 — this copy promises it, so either pull Compress into MVP or hold onboarding launch until Compress ships.
Merged · S4 Folder + ReadyFolder permission and the Ready payoff are now one screen. After user taps Choose Folder → iOS picker → onboarding closes directly into the populated Library. No separate "Ready" screen: the library itself is the reward, and it lives outside onboarding. Headline "Pick your folder. Your library, ready." bridges both concepts in one screen.
Cut · Face ID (S4)Not in the 12-item MVP scope. Deferred to Phase 1 with the rest of the app-lock feature. Users who want it can enable it later from Settings — but we don't promise it in onboarding.
Cut · Paywall (S5)Moved to contextual trigger: first time the user taps a Premium-gated action (e.g. OCR beyond N pages, or bulk merge). Onboarding paywall adds friction before the Aha moment has landed — dangerous while we're still validating the core loop.
Added · S3 ReadyShows a small preview of what the Library will look like after auto-scan lands. Confirms the payoff visually before the user swipes into the app. Reinforces Tủ hồ sơ (status chips visible on doc rows).
Copy shiftWelcome headline no longer says "designed for Apple" — that's a design USP for App Store, not onboarding. Leads with the pain ("never lose track") + the mechanism ("organized by status"). This is the Zeigarnik hook stated plainly.
Progress dots4 dots: Edit → Tools → Never lose track → Folder+Ready. Each feature has its own screen; Tủ hồ sơ closes the feature sequence before the folder Aha moment.

Contextual paywall — where it fires instead

  • OCR: first free scan is unlimited; 2nd time user triggers OCR, show paywall with "Unlimited scans" as the top value.
  • Merge/Split: allow one operation free per launch; 2nd operation shows paywall.
  • E-signature: free — no gate. Sign is the highest-intent action of the freelancer/SMB persona; gating it destroys trust for the anchor segment.
  • Convert-to-ZIP: free.
  • All contextual paywalls reuse the same PaywallView. Track PaywallEntryPoint.contextualOCR / .contextualMerge / etc. to measure which surface converts.

Skip semantics (MVP)

  • S2 skip ("I'll do this later") → advance to S3, but S3 shows an empty-state preview instead of the populated Library (headline shifts to "Add your first document"), and CTA becomes "Grant folder access" reopening the picker. Never leave user on a dead-end.
  • No skip on S3. There's nothing to skip — it's the "you're in" moment.
  • Onboarding rerun: Settings → "Redo onboarding" hidden switch for QA and support. Not in main Settings UI for MVP.

State machine (simplified)

  • OnboardingStep enum: .editOffice → .tools → .neverLoseTrack → .folderAndReady. Complete on .folderAndReady (whether folder granted or skipped) → set @AppStorage("hasCompletedOnboarding") = true.
  • If folder was skipped: still complete onboarding, but flag @AppStorage("librarySeeded") = false so Library shows empty-state CTA.
  • If auto-scan is still running when S3 appears: show a shimmer skeleton for doc rows; the SVG preview above is a placeholder for that state.

Ship metrics to watch on TestFlight

  • Onboarding completion: target ≥ 85%. Below 75% → something on S1/S2 is off.
  • Folder grant rate on S2: target ≥ 60%. Below 40% → trust badge or copy needs work, or move Aha earlier.
  • Time-to-first-open-doc from S3: target ≤ 20s. Above 60s means the Library isn't obviously the payoff.
  • Contextual paywall conversion: track separately per surface. If onboarding-free flow underperforms full-flow paywall on total ARPU, revisit including paywall in onboarding.
