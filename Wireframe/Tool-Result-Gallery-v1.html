Tool Result Gallery — v1

Every tool operation ends at a destination — no more "toast + stay at picker". Single-file outputs auto-navigate to the editor (unchanged). Multi-file outputs (Split N>1, PDF→Image, Scan both formats) present a bottom sheet gallery for review, batch save, and per-file open.

Rule of destination: after processing, ALL tools show a toast at top, then navigate. Single-output → in-app editor (Merge, Convert 3 directions, Scan single, Split N=1). Multi-output → this gallery sheet (Split N>1, PDF→Image, Scan PDF+DOCX).

Component: ToolResultGalleryView — bottom sheet at .large detent. Grid layout for images (2 cols, aspect 3:4). List rows for documents (icon · name · size). Bottom action bar: Save All to Files + Share All. Tap a tile/row → open (editor for PDF/DOCX, QuickLook for images).

Decisions to confirm:

1. Sheet vs push? Bottom sheet at .large detent — dismissable via Done or swipe-down. Alternative: NavigationLink push. Sheet feels more "result inspection", push feels more "next step". Recommend sheet.

2. Grid vs list? Images = grid (visual matters). PDFs/DOCX = list rows (metadata matters). Split shown as list even though homogeneous — page count + size differentiate them.

3. Select mode? "Select" nav button (top-right) for future per-item batch actions (delete some, share some). V1 can skip Select, just Save All + Share All. Add later if user asks.

4. Where do files live on disk? Currently all outputs land in FileManager.default.temporaryDirectory or app Documents/. Verify: if Documents/, Library scanner picks them up automatically after gallery dismisses. If temp, "Save All" is the ONLY way user keeps them.

5. Empty case? Gallery only appears when count > 0 (guarded already). Count == 1 special-case: skip gallery, auto-navigate directly (matches Merge/Convert single).
